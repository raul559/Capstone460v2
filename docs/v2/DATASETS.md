# SkinAI Master Dataset

File: `docs/v2/DATASETS.md`

How the SkinAI master dataset is built from seven public skin-lesion sources,
what each output is, and where it is kept. Converted from Emma Lytle's
"SkinAI Dataset Process Overview, File Map, and PR Description" (originally a
.docx, drafted with Perplexity). File locations are updated to where they live
in this repository.

Related:

- [`ANATOMICAL_SITE_MAPPING.md`](ANATOMICAL_SITE_MAPPING.md): how anatomical
  sites are harmonized across sources
- [`models/datasets/skinai-master/`](../../models/datasets/skinai-master/README.md):
  committed summaries, checksums, class mapping, and split config
- [ADR 0001](../architecture/decisions/0001-master-dataset-and-8-class-retraining.md):
  the open decision on retraining with the 8-class mapping

> This dataset is training input for a possible future model. The deployed
> model is still the V1 seven-class ResNet50. Nothing here changes model
> behavior until ADR 0001 is accepted.

## What is and is not in Git

| Kept in Git | Kept out of Git |
|---|---|
| Build scripts and notebooks (`scripts/models/dataset/`) | Source images (Hugging Face storage bucket `sarcolemma/SkinAI`, as ZIPs under `Images/`) |
| Per-source and per-split counts, coverage reports | Source metadata CSVs (each developer's `SKINAI_METADATA_DIR`) |
| SHA-256 pins for the master manifest and inputs | Row-level manifests: `master.parquet`, per-split CSV/parquet files, audit tables |
| `class_mapping.json`, `split_config.json`, reviewed near-duplicate rejections | Anything with one row per image or patient |

Row-level files are regenerated by the scripts and checked against the
committed SHA-256 pins. They are not committed because of size (about 283 MB),
because they carry per-patient health fields, and because some source datasets'
terms may not allow redistribution. `manifests/` is git-ignored so a local
rebuild cannot be committed by accident.

## Process overview

### 1. Seven dataset loaders

Notebook cells were written for all seven sources: ISIC 2019, MILK10k,
Fitzpatrick17k, PAD-UFES-20, HIBA, MRA-MIDAS, and DDI. Each produces rows in
one shared canonical schema. Design decisions:

- All loaders read from a single metadata folder, with image references
  resolved relative to that folder.
- Every loader keeps the raw source label verbatim (`disease_label`) and maps
  it separately to the harmonized class (`label_class`) and classification
  (`disease_classification`) through literal dictionaries in shared notebook
  cells.
- Melanocytic/melanoma-only exclusions were dropped from scope by decision.
  Unknown classes map to `pd.NA` rather than an "unknown" bucket.
- Tone handling follows each source: Fitzpatrick types normalized to 1-6; DDI
  keeps paired I-II / III-IV / V-VI groups in `fitzpatrick_group` with
  individual `fitzpatrick` as NA; MILK10k stores ITA estimates with
  `tone_provenance = ita_estimate`.
- Pathology confirmation is explicit: `0` only when a source states
  histopathology did not confirm; missing status is NA.

### 2. Anatomical site harmonization

A two-level site mapping (broad `anatomical_site` plus
`anatomical_site_detail`) is applied inside each loader. MRA-MIDAS free-text
locations have a complete dictionary covering every raw location string, with
seven deliberately unmapped values left as NA. See
[`ANATOMICAL_SITE_MAPPING.md`](ANATOMICAL_SITE_MAPPING.md).

### 3. Master build and archive validation

`build_master.py` runs the seven loaders, validates the shared schema (no
unknown columns, no duplicate references, label and split checks), and writes
`master.parquet` with a SHA-256 pin and validation reports.

The remote ZIP check first failed on 64,823 inner paths because of inner-folder
prefixes. Fixed per dataset:

| Source | Fix |
|---|---|
| ISIC 2019 | prefix `ISIC_2019_Training_Input/` from the archive stem |
| MILK10k | `milk10/` |
| HIBA | `hiba-skin-lesions/` |
| PAD-UFES-20 | `PAD-UFES-20/` (nested ZIPs flattened by hand first) |
| Fitzpatrick17k | 114 subfolders handled through a generated lookup CSV (`fitzpatrick17k_zip_paths.csv`) |
| MRA-MIDAS | filenames corrected by hand in `mra-midas-corrected.csv`; 17 unresolvable references excluded via `mra_exclusions.csv` (3,399 of 3,416 rows kept) |

The final build passed with 68,614 rows against the committed
`expected_counts.csv` baseline.

### 4. Image audit and leakage control

`image_audit.ipynb` runs a resumable decode-and-hash pass over all 68,614
images (byte MD5 and SHA-256, pixel SHA-256, pHash), then:

- **Exact duplicates:** 65 rows excluded as `redundant_exact_pixels`, keeping
  one representative per pixel-identical group.
- **Label conflicts:** 30 rows quarantined as `exact_label_conflict`:
  pixel-identical images with different diagnoses (2 ISIC groups, 13 PAD
  groups). Kept excluded rather than resolved by majority vote or filename.
- **Near-duplicate screening:** a BK-tree search over perceptual hashes
  (Hamming distance ≤ 4) found 4,282 candidate pairs. All pairs stay linked
  unless explicitly rejected.
- **Leakage grouping:** patient and lesion IDs, exact duplicates, and
  similarity links merge images into leakage groups. Splits are assigned per
  group, so no patient or lesion spans two splits.

### 5. Manual boundary review

Eight candidate pairs crossed the development/external boundary and were
reviewed side by side:

- 2 pairs confirmed as exact duplicates (ISIC images of the same lesion as MRA
  `s-prd-501817652`). Links kept; development-side copies excluded.
- 4 pairs confirmed as different lesions, recorded in
  `near_duplicate_rejections.csv` and unlinked.
- 2 pairs (MRA `s-prd-704414306` and `s-prd-719315705` matching ISIC nevi)
  kept as same-lesion matches.

A false start worth knowing: the first rerun after hand-editing the rejection
CSV produced an unchanged report, because hand-typed image references did not
match exactly. Copying the references from the candidate table fixed it.

### 6. Final state

- 104 exclusions: 65 redundant pixels, 30 label conflicts, 9 external-group
  overlap.
- 68,510 retained rows.
- Grouped 80/10/10 development split (train / validation / internal test),
  with DDI and MRA-MIDAS held out entirely as `external_test`. Exported for
  both the full condition set and the predefined 8-class subset (MEL, NV, BCC,
  AK, BKL, DF, VASC, SCC).

### Limitations (also recorded in `split_config.json`)

- pHash screening can miss transformed copies (crops, rotations, overlays) and
  can over-group unrelated images.
- Unknown patient or lesion identities across sources remain unverified.
- Readable images are not guaranteed clinically usable or correctly labeled.
  The exported splits are candidates for training, not a certification of
  validity.

## File map

### Code: `scripts/models/dataset/`

| File | Purpose |
|---|---|
| `dataset_loaders.ipynb` | Shared mapping cells (classification map, tone rules, site maps, MRA dictionary) plus one loader cell per dataset; bridge cell that calls `build_master.py` |
| `build_master.py` | Runs the 7 loaders, validates the canonical schema, writes `master.parquet` and validation reports |
| `test_build_master.py` | Synthetic unit tests for the builder (schema, validation, ZIP checks) |
| `image_audit.ipynb` | Decode and hash, duplicates, leakage groups, split export |

Described in the original document but not yet in the repository:
`anatomical_site_mapping.py`, `test_anatomical_site_mapping.py`,
`mra_site_map.py`, `mra_site_mapping_lookup.csv`, and the build README and
walkthrough notes.

### Source metadata helpers (in `SKINAI_METADATA_DIR`, not committed)

| File | Purpose |
|---|---|
| `fitzpatrick17k_zip_paths.csv` | Image filename to ZIP inner path lookup for Fitzpatrick17k's 114 subfolders |
| `mra-midas-corrected.csv` | Hand-corrected MRA-MIDAS filename references |
| `mra_exclusions.csv` | 17 MRA rows dropped because their image references could not be resolved |

### Committed summaries: `models/datasets/skinai-master/`

See that folder's [README](../../models/datasets/skinai-master/README.md).

### Local outputs: `manifests/` (git-ignored)

| File | Purpose |
|---|---|
| `master.parquet` | The 68,614-row source-linked master manifest |
| `validation/` | Build-time reports, including row-level ones (`image_ref_checks.csv`, `unmapped_rows.csv`) |
| `image_audit/<hash>_v1/` | Audit output keyed by master hash and audit version: excluded rows, label conflicts, near-duplicate candidates, clean split, per-split manifests for all conditions and the 8-class subset |

## How to run

Prerequisites: Python 3.12, `pandas`, `pyarrow`, `huggingface_hub` (logged in
locally with read access to the bucket; never paste a token into a notebook),
and for the audit `Pillow`, `ImageHash`, `scikit-learn`, `tqdm`.

```bash
# Unit tests (synthetic data, no bucket access needed)
python -m unittest discover -s scripts/models/dataset -p "test_*.py"

# Where the source metadata CSVs live on your machine
export SKINAI_METADATA_DIR=/path/to/Datasets/metadata
```

Then run `dataset_loaders.ipynb` from `scripts/models/dataset/` (it builds
`manifests/master.parquet`), and `image_audit.ipynb` end to end (resumable).
Compare `manifests/master.parquet` against
`models/datasets/skinai-master/master.parquet.sha256`.

The dataset tests are not yet part of CI, which installs only the API's
dependencies.
